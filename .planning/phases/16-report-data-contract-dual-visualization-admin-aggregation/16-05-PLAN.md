<objective>
Close the two major UAT gaps from Phase 16 human verification, both in the shared report-rendering layer:

- **G-16-1:** Radar-chart left-side axis labels ("Control over Data & Trust", "Value Creation") are clipped at the SVG's left edge in BOTH the in-app browser view and the WeasyPrint PDF. Root cause: `generate_radar_svg()` hardcodes `text-anchor="middle"` for every label, centering long left-side labels on an anchor point too close to the viewBox edge so their leading characters overflow x=0 and get clipped by the SVG's own viewBox.
- **G-16-2:** In the PDF only, the priority-area score column doesn't align (tracks the label text width instead of sitting flush right) and the legend wraps to a second line unnecessarily. Root cause: `report.html` nests `display:flex` inside `display:flex` (`.priority-name` inside `.priority-row`, `.legend-item` inside `.legend`), which triggers documented WeasyPrint 69.0 bugs in `justify-content` free-space distribution and intrinsic-width calculation.

Purpose: The report is the product's payoff surface (PROJECT.md core value). Both gaps make the delivered PDF/in-app report look broken to the end user.
Output: Corrected `generate_radar_svg()`, flattened `report.html` priority-row/legend structure, backend regression tests, and a human visual confirmation on a real WeasyPrint render.
</objective>

    - For a 6-axis chart (axes evenly spaced starting straight up), the rendered SVG contains exactly 2 labels with text-anchor="middle" (top axis i=0 and bottom axis i=3, where cos(angle) ≈ 0), exactly 2 with text-anchor="start" (right-side axes, cos>0), and exactly 2 with text-anchor="end" (left-side axes, cos<0).
    - The SVG viewBox is widened horizontally so its min-x is negative and its width exceeds its height, giving end-anchored left labels and start-anchored right labels room to render fully (the longest real category name, "Control over Data & Trust", must not overflow either horizontal edge).

  </behavior>
  <action>
    In generate_radar_svg(), stop emitting a uniform text-anchor for every axis label. Compute each label's anchor from the horizontal component of its axis angle:
    - Reuse the angle already computed for each axis (angle = 2*pi*i/n - pi/2). Derive cos(angle).
    - When cos(angle) is within a small epsilon of 0 (the top and bottom axes) use text-anchor "middle"; when cos(angle) is positive (right side) use "start"; when negative (left side) use "end". Pick epsilon generous enough that the exactly-vertical top/bottom axes classify as middle for any axis count (a value on the order of 1e-6 suffices since those cosines are mathematically zero, but a small positive epsilon guards float noise).
    - Interpolate the chosen anchor into the existing <text> element in place of the current fixed value. Keep the existing font-size, font-family, fill attributes and the xml_escape(...) of the category name exactly as-is — do not weaken the WR-05 escaping (threat T-16-05-01).

    Then widen the SVG viewBox so the newly outward-growing labels are not clipped. The current viewBox pins x to 0..size, which is the clip source. Replace it with a horizontally padded viewBox: keep the vertical range at 0..size, but extend it left of 0 and right of size by a generous horizontal margin sized for the longest real category name at the 11px label font (min-x negative, total width noticeably greater than height). The geometry itself (cx/cy from size, radius, point()) stays centered and unchanged — only the visible window widens. Do not hardcode assumptions that only apply to n=6; base the margin on giving long labels room, not on a specific axis count.

    Add regression tests to test_report_generator.py driven from the real config (mirroring the existing _config()/_six_scores() helpers):
    - Assert the rendered SVG contains exactly two occurrences each of the three anchor values for the 6-category config (2 middle, 2 start, 2 end).
    - Assert the viewBox's first coordinate (min-x) parses to a negative number and the viewBox width is greater than its height.
    - Leave the existing test_radar_svg_structure and test_radar_svg_escapes_special_characters_in_category_name assertions passing unchanged.
  </action>
