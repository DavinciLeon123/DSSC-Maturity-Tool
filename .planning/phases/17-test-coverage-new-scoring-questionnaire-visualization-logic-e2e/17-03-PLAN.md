Close Phase 17's E2E obligation (TEST-03): a Chromium-only Playwright suite that drives the real
critical path — register, answer all 52 questions, submit, view the report — through the actual
browser UI against the real `docker-compose.yml` stack (db + backend + frontend), running as a new
CI job on `staging.yml`/`main.yml` only (never `pr.yml`, mirroring the existing `perf`/`benchmark`
marker precedent this repo already uses to keep PR feedback fast).

17-RESEARCH.md surfaced 2 load-bearing facts that shape this plan directly:
1. **Nest nothing inside `frontend/`.** Vitest's default include-glob, ESLint's unscoped `files:
   ['**/*.{ts,tsx}']`, and `tsconfig.app.json` would all pick up Playwright spec files and choke
   on them (wrong runtime, colliding global `test`/`expect` identifiers). The whole suite lives in
   a new top-level `e2e/` directory, sibling to `frontend/`/`backend/`, entirely outside every
   existing tool's scan root.
2. **`staging.yml` and `main.yml` need DIFFERENT image-sourcing**, not identical jobs.
   `staging.yml`'s `docker-build` job pushes real `:staging`-tagged images to `ghcr.io` — the e2e
   job there pulls and reuses them. `main.yml`'s `docker-build-and-sbom` job builds with `push:
   false, load: true` — those images exist only in that other job's own ephemeral Docker daemon
   and are NOT reachable from a separate job. `main.yml`'s e2e job instead runs its own `docker
   compose up --build` from source. Both paths are served by one reusable workflow
   (`e2e-tests.yml`, `on: workflow_call`) taking optional image-tag inputs, avoiding ~40 lines of
   duplicated "start compose, wait for readiness, run playwright, upload on failure" logic.

Purpose: prove the shipped, built-image topology actually works end-to-end before code reaches a
shared/protected branch.
Output: a new `e2e/` Playwright project; a new reusable `e2e-tests.yml` workflow; one new `e2e` job
added to each of `staging.yml` and `main.yml`.

this is a genuine race if skipped, not a hypothetical one.

**Docker Compose readiness (RESEARCH Pitfalls 6/7):** `docker-compose.yml` only healthchecks the
`db` service — `backend`/`frontend` have none, so `docker compose up --wait` alone is NOT a valid
readiness gate (a container with no healthcheck is treated as "ready" the instant its process
starts, well before `alembic upgrade head` finishes). Use `docker compose up -d` (no `--wait`)
followed by a separate HTTP-level `wait-on` step against `http://localhost:8000/health` (exists at
`backend/app/main.py:66`, returns `{"status": "ok"}`) and `http://localhost:3000`. The backend
container also hard-crashes at startup without a full `.env` matching `.env.example`'s 5 keys
(`POSTGRES_USER`, `POSTGRES_PASSWORD`, `SECRET_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`) — write one
with fixed throwaway CI-only values before `docker compose up`.

**Image-sourcing without touching `docker-compose.yml`'s `build:` blocks:** a Compose override
file adding `image:` to a service that already has `build:` does NOT force a rebuild — `docker
compose up -d` (no `--build` flag) uses an already-present local image tag directly rather than
building from `build:`. So: `docker pull <ghcr tag>` first (which locally tags the image under
that exact name), THEN `docker compose -f docker-compose.yml -f e2e/docker-compose.e2e.yml up -d`
— Compose sees the image already exists locally and skips building. `main.yml`'s from-source path
simply never applies the override file and runs `docker compose up -d --build` against the base
file directly.

`staging.yml`'s `docker-build` job's existing outputs (already defined, reuse directly — do not

```typescript
import { test, expect } from '@playwright/test';

// TEST-03: the one critical-path E2E test this phase requires — register, answer the full
// 52-question assessment, submit, view the report. Runs against the real docker-compose stack
// (see e2e-tests.yml), never mocked. No data-testid exists anywhere in this codebase (confirmed
// via repo-wide grep, 17-RESEARCH.md) — every locator below is role/placeholder/type-attribute
// based, traced directly against the real component source.
test('critical path: register -> answer questionnaire -> submit -> view report', async ({ page }) => {
  const email = `e2e-${Date.now()}@example.com`;
  const password = 'Str0ngPassw0rd!123';

  // ---- Register --------------------------------------------------------
  await page.goto('/register');
  await page.locator('input[type="email"]').fill(email);
  await page.locator('input[type="password"]').fill(password);
  await page.getByRole('checkbox').check();
  await page.getByRole('button', { name: 'Register' }).click();
  await page.waitForURL('**/login');

  // ---- Login -------------------------------------------------------------
  await page.locator('input[type="email"]').fill(email);
  await page.locator('input[type="password"]').fill(password);
  await page.getByRole('button', { name: 'Sign In' }).click();
  await page.waitForURL('**/dashboard');

  // ---- Register initiative ------------------------------------------------
  await page.getByPlaceholder('Enter initiative name').fill('E2E Test Initiative');
  await page.getByText('Select a sector...').click();
  await page.getByRole('option', { name: 'Healthcare' }).click();
  await page.getByRole('button', { name: 'Register Initiative' }).click();

  // ---- Start the assessment (fresh draft -> straight to /questionnaire, no retake confirm) ---
  await page.getByRole('button', { name: 'Start Dataspace Maturity Assessment' }).click();
  await page.waitForURL('**/questionnaire');

  // ---- Welcome screen (always shown for a fresh draft) -------------------
  await page.getByRole('button', { name: 'Begin assessment →' }).click();

  // ---- Answer all 6 category pages, always the 3rd (middle) option per question ------------
  for (let categoryPage = 0; categoryPage < 6; categoryPage++) {
    // handleNext() is async (awaits a real backend flush before navigating) — wait for the new
    // category's radiogroups to actually render before re-querying, a genuine race otherwise.
    await expect(page.getByRole('radiogroup').first()).toBeVisible();
    const groups = await page.getByRole('radiogroup').all();
    for (const group of groups) {
      await group.getByRole('radio').nth(2).click();
    }
    const isLastCategory = categoryPage === 5;
    const buttonName = isLastCategory ? 'Submit assessment →' : 'Next →';
    await page.getByRole('button', { name: buttonName }).click();
  }

  // ---- Post-submit: generate + view report --------------------------------
  await expect(page.getByText('Thanks for completing the survey.')).toBeVisible();
  await page.getByRole('button', { name: 'Generate heatmap' }).click();
  await page.waitForURL('**/report');

  // ---- Report renders (radar chart + priority list) — structural assertions only; ----------
  // ---- per-row/attribute detail is covered by Plan 17-02's Vitest report.test.tsx. ---------
  await expect(page.getByText('Maturity radar')).toBeVisible();
  await expect(page.getByText('Priority areas')).toBeVisible();
  await expect(page.locator('svg').first()).toBeVisible();
});
```

**Create `.github/workflows/e2e-tests.yml`** (reusable, `on: workflow_call`, takes optional
pre-built image tags — empty means "build from source"):
```yaml
name: E2E Tests (reusable)

on:
  workflow_call:
    inputs:
      backend-image:
        description: "Pre-built backend image to pull (ghcr tag). Empty = build from source."
        required: false
        type: string
        default: ""
      frontend-image:
        description: "Pre-built frontend image to pull (ghcr tag). Empty = build from source."
        required: false
        type: string
        default: ""

env:
  NODE_VERSION: "20"

jobs:
  e2e:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: read
    steps:
      - uses: actions/checkout@v4

      - name: Write throwaway CI .env
        # Fixed, ephemeral, CI-only values — never production secrets (the Postgres container
        # itself is fresh/ephemeral per run anyway). backend/scripts/create_admin.py crashes the
        # container at startup without all 5 of these set, matching .env.example's keys.
        run: |
          cat > .env <<'EOF'
          POSTGRES_USER=e2e_user
          POSTGRES_PASSWORD=e2e_ci_password_throwaway
          SECRET_KEY=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcd
          ADMIN_EMAIL=admin@e2e.local
          ADMIN_PASSWORD=E2eAdminPassw0rd!123
          EOF

      - name: Log in to GHCR (only needed when pulling pre-built images)
        if: inputs.backend-image != ''
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Pull pre-built images and start stack (staging path)
        if: inputs.backend-image != ''
        run: |
          docker pull ${{ inputs.backend-image }}
          docker pull ${{ inputs.frontend-image }}
          E2E_BACKEND_IMAGE=${{ inputs.backend-image }} E2E_FRONTEND_IMAGE=${{ inputs.frontend-image }} \
            docker compose -f docker-compose.yml -f e2e/docker-compose.e2e.yml up -d

      - name: Build from source and start stack (main path — main.yml never pushes images)
        if: inputs.backend-image == ''
        run: docker compose up -d --build

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}

      - name: Wait for backend + frontend to be ready
        # docker-compose.yml only healthchecks `db` — backend/frontend have none, so an HTTP-level
        # check is required; `docker compose up --wait` alone would falsely report ready the
        # instant the container process starts, before alembic upgrade + admin seed finish.
        run: npx --yes wait-on http://localhost:8000/health http://localhost:3000 -t 120000

      - name: Install Playwright
        working-directory: e2e
        run: |
          npm ci
          npx playwright install --with-deps chromium

      - name: Run Playwright critical-path suite
        working-directory: e2e
        run: npx playwright test

      - name: Dump docker compose logs on failure
        if: failure()
        run: docker compose logs

      - name: Upload Playwright report/trace on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report-${{ github.run_id }}
          path: |
            e2e/playwright-report
            e2e/test-results
          retention-days: 14

      - name: Tear down stack
        if: always()
        run: docker compose down -v
```
