<objective>
Fix Bug #6 (buttons and cards have rounded corners; DSSC's brand style at dssc.eu uses square corners) — per CONTEXT.md's locked decision D-01, this covers BOTH buttons AND cards, not buttons alone (research's own default recommendation was buttons-only; the user explicitly expanded scope to include cards in this phase).

Root cause (per `16.3-RESEARCH.md`, confirmed live against `https://dssc.eu`'s compiled CSS: `.btn{border-radius:0}`, `.card{border-radius:var(--radius-none)}` where `--radius-none:0px`): `theme.ts`'s antd `ConfigProvider` theme currently sets `Button`/`Card` corner radii to 8px/16px, AND — more importantly — the overwhelming majority of `<Button>`/`<button>`/card-like elements across ~17 files carry an inline `style={{ borderRadius: "8px" }}` (or similar) override that always wins over any theme-token change (Pitfall 4: inline styles beat theme tokens). `WizardPage.tsx`'s Previous/Next/Retry-save controls are plain native `<button>` elements, invisible to antd theming entirely (Pitfall 5) — they need direct edits regardless of what `theme.ts` does.

Purpose: this plan was run 100% by direct source reads of every `borderRadius` occurrence in `frontend/src` (90 raw matches, individually classified below) — not a blanket find-and-replace. Elements explicitly OUT of scope per the bug report's wording and D-01's own carve-out: alert banners (antd `<Alert>`), badges/pills (`border-radius: 100px`/`50%` status pills), decorative circles (radio buttons, status dots, step-progress indicators), `Input`/`Select`/`TextArea` fields, and antd `<Table>` wrapper radii. Card-like plain `<div>`s that visually function as a Card (white/light background + padding + shadow, grouping content) ARE in scope — CONTEXT.md's own words: "unless a planner/executor finds it's the same Card component under a different name."
Output: a component-scoped `theme.ts` change (NOT the root token — see Task 1's rationale) plus ~53 individual inline-style value changes across 17 files.
</objective>
