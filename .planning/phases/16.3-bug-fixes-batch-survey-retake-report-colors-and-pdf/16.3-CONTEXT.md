## Bug Reports (verbatim from user, unedited)

### Bug #1 — Retaking the survey fails to save
As a user, when I have already completed my first survey, and I try to retake the survey via the Dropdown Menu that points to `[base_url]/questionnaire` I can start filling the survey, however it gives an error when trying to save the data.
This is likely because it doesn't register as a new (second, third, etc) survey.

### Bug #2 — Questionnaire text is blue, should be black
The questions and the answers in the questionnaire itself are blue. This should be black for readability.

### Bug #3 — "View Report" always shows/downloads the newest survey, not the one clicked
As a user, when I want to view the report of a previous survey (after taking at least 2), I click on View Report. That page, however, only gives me the most recent scores and graph. And also results in the newest report to be downloaded.
The Assessment History page does show the right numbers for both the most actual and previous surveys taken.

### Bug #4 — PDF report missing "For the initiative:" label
In the PDF report, under the heading "Your DSSC Maturity Report" it states the name of the DSI. Before that, it should read "For the initiative:".

### Bug #5a — PDF score status dot is clipped
In the PDF report, the color of the score is cut off. Next to the actual score (1.00 to 5.00) there is a small hint of a green, orange or red dot, but it doesn't fully show.

### Bug #5b — "Get expert help" box wording (mislabeled "Bug #5" by user, treated as 5b)
In the PDF report, at the end of the report there is the box "Get expert help". The first sentence afterwards reads "The Centre of Excellence is here to help you navigate…". That should be the Data Spaces Support Centre.

### Bug #6 — Buttons should not have rounded corners (DSSC style)
All the buttons now have rounded corners. The style of the DSSC however is no round corners. So please take another look at https://dssc.eu and change them.

### Bug #7 — Admin panel: show completed-assessment count, not raw answer count
In the Admin Panel, on the second tab called Dataspace Maturity Assessments, I see the total Answers per user. Whenever I see a figure higher than 52, I know they've at least started it a second time. Instead I would like to see how many completed assessments there are for each user. And perhaps a symbol that they're underway with a next one.
</bug_reports>

## Notes for discuss-phase / plan-phase (not decisions — starting points only)

- Bug #1/#3/#7 all plausibly trace back to the same root cause: the app's Assessment model (added Phase 13, `backend/app/models/assessment.py`) supports multiple Assessments per Initiative (draft/submitted lifecycle), but retake/report/admin code paths may still assume "one assessment" and always resolve the latest or the only one — worth checking `assessment_id` resolution in the questionnaire-answer PUT endpoint, `/report` and `/report/data` (`backend/app/api/v1/reports.py`), and the admin aggregation endpoint (`backend/app/api/v1/admin.py`) together before assuming they're 3 unrelated fixes.
- Bug #2/#6 are styling-only — Phase 16.2/16.1 already established the DSSC token set (`--dssc-*` CSS vars, `theme.ts` antd `ConfigProvider`) as the source of truth; likely just wrong hardcoded colors (blue-on-blue) and `borderRadius` tokens rather than needing new tokens.
- Bug #4/#5a/#5b are all in `report.html` (WeasyPrint PDF template) per Phase 16's shared-contract work — likely a small, contained set of template edits.
- The "52" reference in Bug #7 matches the real total question count confirmed in this repo's own history (8+9+6+9+9+11 = 52 across 6 categories, per Phase 16.2 session notes) — a useful sanity check when validating a fix, not a hardcoded value to copy into new code without checking the live config.
</likely_areas_for_investigation>

<decisions>
## Implementation Decisions (locked, resolving 16.3-RESEARCH.md's Open Questions #2 and #3)

### Bug #6 scope — buttons AND cards (D-01)
Research confirmed DSSC's live site (`https://dssc.eu`'s compiled CSS, fetched directly) uses `border-radius: 0` for both `.btn` and `.card`. Research's default recommendation was buttons-only (matching the bug report's literal wording), flagging cards as a discretionary fast-follow. **User decision: do both together in this phase** — square off cards' corners alongside buttons', not as a separate future phase. Still explicitly out of scope: any other rounded element not covered by this decision (alert banners, badges/pills, pure decorative shapes) unless a planner/executor finds it's the same `Card` component under a different name.

### Bug #7 scope — fix both the Assessments tab AND the Users tab (D-02)
Research confirmed the Admin Panel's separate **Users** tab (`admin.index.tsx`'s `usersExpandable` row, "Answers saved" field, sourced from `list_users()` in `admin.py`) has the identical raw-answer-count defect as the reported "Dataspace Maturity Assessments" tab, just via a different endpoint/query. The bug report only named the Assessments tab. **User decision: fix both tabs for consistency** — same completed-assessment-count + in-progress-indicator treatment applies to `list_users()`/the Users tab's "Answers saved" field, not just `list_initiatives()`/the Assessments tab.

</decisions>
