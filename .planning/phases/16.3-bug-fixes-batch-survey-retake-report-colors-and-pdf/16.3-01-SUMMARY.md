# Phase 16.3 Plan 01: Retake-Save Fix (Shared Confirm-Then-Retake Hook) Summary

**Extracted dashboard.tsx's confirm-then-retake logic into a shared `useStartOrRetakeAssessment()` hook, wired TopNav's nav-drawer item and dashboard's CTA through it, and added a defense-in-depth redirect in questionnaire.tsx so no UI path into `/questionnaire` can skip the retake gate for a submitted initiative.**

## Performance

- **Duration:** ~12 min
- **Tasks:** 2 completed
- **Files modified:** 4 (1 created, 3 modified)

## Accomplishments
- Closed Bug #1: the TopNav nav-drawer's "Dataspace Maturity Assessment" link previously navigated straight to `/questionnaire` with no retake logic, causing every save to 403 for a user with a `submitted` initiative
- `frontend/src/lib/retake.ts` is now the single implementation of the confirm-then-retake flow, consumed identically by `TopNav.tsx` and `dashboard.tsx`
- Added a defense-in-depth mount-time redirect in `questionnaire.tsx` for any future/bypassed entry point that lands on a submitted initiative

## Task Commits

Each task was committed atomically:

1. **Task 1: Create the shared useStartOrRetakeAssessment hook** - `e3742af` (feat)
2. **Task 2: Wire TopNav, Dashboard, and the questionnaire guard to the shared hook** - `ea23e4e` (feat)

_Note: Task 1's file (`frontend/src/lib/retake.ts`) was already present in the working tree, verbatim-correct against the plan, from a prior crashed execution attempt (API error, unrelated to this plan's content) that never committed anything — verified via `tsc -b --noEmit` before committing rather than blindly recreated._

## Files Created/Modified
- `frontend/src/lib/retake.ts` - `useStartOrRetakeAssessment()` hook: fetches `/initiatives/me` fresh on every call, shows the `Modal.confirm` retake dialog if `status === "submitted"`, calls `POST /initiatives/{id}/retake` then navigates to `/questionnaire`, else navigates straight through
- `frontend/src/components/layout/TopNav.tsx` - Nav-drawer "Dataspace Maturity Assessment" item now has a per-item `onClick` (`preventDefault` + `setDrawerOpen(false)` + `void startOrRetake()`) instead of a bare `<Link>` navigation; other nav items (`Dashboard`/`About`/`Admin`) keep their unchanged plain-navigation `onClick`
- `frontend/src/routes/_app/dashboard.tsx` - `handleStartOrRetake` now delegates to the shared hook (`void startOrRetake()`); the inline `Modal.confirm` block and the now-unused `Modal` import were removed
- `frontend/src/routes/_app/questionnaire.tsx` - Added `status` to the fetched initiative shape and a `useEffect` that redirects to `/dashboard` if `initiative?.status === "submitted"`

## Decisions Made
- Kept `useNavigate()` called internally inside the hook (per the plan's explicit instruction) rather than accepting `navigate` as a parameter, avoiding TanStack Router's route-tree-inferred generic type across a hand-typed function boundary
- Did not touch the confirm-modal copy or the retake endpoint call — this was a lift-and-shift of already-correct, already-tested logic into reusable form, not a rewrite
- Left the effect-based redirect in `questionnaire.tsx` without a render-time early return, per the plan's explicit instruction — the confirm UX remains exclusive to the shared hook
