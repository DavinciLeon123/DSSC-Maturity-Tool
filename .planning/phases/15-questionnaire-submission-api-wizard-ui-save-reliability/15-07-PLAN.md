<objective>
Close Gap 2 (HIST-02): assessment history is not actually frozen. `compute_dimension_scores` always derives category names, per-category question counts, and score divisors from the LIVE config injected at request time — never the config as it was when the assessment was submitted. The config is explicitly documented as a placeholder pending real QSTN-05 content, so once it changes (which it will), every previously-submitted version's displayed scores silently drift to reflect the new config, contradicting the phase goal's "permanently preserved assessment version" guarantee.

This plan persists a frozen `dimension_scores` JSON snapshot on the `Assessment` row at the moment `submit_initiative` flips it to `submitted`, and makes the history endpoint prefer that snapshot over live recomputation. It also corrects the REQUIREMENTS.md traceability drift the verifier flagged.

Purpose: make submitted history immutable so "compare scores across your past versions" always reflects what the user actually submitted.
Output: a snapshot column + migration, submit-time freezing, snapshot-preferring history read, a zero-division guard, tests, and corrected requirement traceability.

Depends on 15-06: both plans modify `backend/app/api/v1/initiatives.py` (15-06 adds the retake endpoint; this plan edits submit_initiative and _to_summary), so this runs in the wave after 15-06.
</objective>

| client -> API (GET history) | Authenticated user reads historical scores for an initiative id in the URL |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-07-01 | Tampering | historical dimension scores | high | mitigate | Scores frozen as a JSON snapshot at submit time; history reads the snapshot, so a later config edit cannot retroactively alter a submitted version (Tasks 1-3) |
| T-15-07-02 | Denial of Service | compute_dimension_scores on submit | low | mitigate | WR-04 zero-division guard prevents an unhandled 500 when a config category has zero questions (Task 2) |
| T-15-07-03 | Information Disclosure | GET /assessments | low | mitigate | Existing owner re-derivation (404/403) on list_assessment_history is unchanged; snapshot data is only ever returned to the initiative owner |
</threat_model>
