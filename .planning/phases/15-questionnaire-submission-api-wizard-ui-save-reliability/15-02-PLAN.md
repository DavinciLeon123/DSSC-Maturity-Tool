<assumption_delta_decision>
Detector `assumption-delta scan 15` returned detected:false on ROADMAP prose, but the phase carries a real singular→plural transition flagged by the assumption-delta contribution: Assessment moves from an implicit "one current row per initiative" model (Phase 13 draft-only semantics) to an explicit "many submitted rows + one draft" versioned-history model (HIST-01/HIST-02).

- Noun now primary for the history surface: **submitted assessment version** (an ordered history), a genuinely different noun from the draft "current assessment."
- Decision: **add-alongside** (not promote/replace). `get_current_assessment` (draft-only, dimension_scoring.py) is deliberately NOT generalized. A new, separate `list_submitted_assessments` helper answers the plural/history question.
- Rationale (RESEARCH Pitfall 5): "what am I filling in now" (draft) and "what have I finished" (submitted history) are different questions; conflating them risks surfacing an in-progress draft as a completed version. Keeping two queries is the correct model, not accepted debt — the draft "current assessment" concept remains valid and unchanged; history is a new primary noun layered beside it.
</assumption_delta_decision>

<objective>
Build the greenfield read-side of retake history (HIST-02): a new GET /initiatives/{id}/assessments endpoint that lists an initiative's submitted assessment versions with per-dimension scores, powering both the history list (D-16a) and the per-dimension comparison table (D-16b) the frontend renders in 15-05.

Purpose: HIST-02 requires the user to view and compare scores across past versions; this endpoint is the single data contract for that view, reusing Phase 14's scoring service rather than re-deriving it.
Output: AssessmentSummary schema, a submitted-assessments query helper, the new route, and integration tests.
</objective>
