<objective>
Add the backend data-integrity spine for versioned retakes and reliable saves: (1) HIST-01/D-15 — compute and increment Assessment.version on draft creation instead of always defaulting to 1; (2) SAVE-03 — replace the IP-keyed answer-save rate limit with a per-authenticated-user key function; (3) SAVE-04/D-08 — persist "last viewed category" server-side so a hard-refresh resumes where the user was. All three require a single hand-written Alembic migration (the [BLOCKING] task) that adds a (initiative_id, version) unique constraint and a nullable last_viewed_category_id column to the assessment table.

Purpose: These are the write-side invariants everything else in the phase depends on — the version number must be assigned correctly and race-safely, and the rate limit must not throttle a user's own legitimate autosave burst.
Output: Modified Assessment model, one new migration, modified questionnaire.py, and Wave-0 unit/migration tests for the new logic.
</objective>
