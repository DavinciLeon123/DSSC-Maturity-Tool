# Phase 16.1: DSSC Rebrand — Visual Identity, Terminology, PDF Content & Registration Default - Context

**Gathered:** 2026-08-02
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase replaces every trace of the old CoE-DSC/MAMI identity with DSSC's real brand identity (now available — official design manual + logo files provided this session), across both the app and the mailed/downloaded PDF report; adds a new per-question submitted-answers section to the PDF only; and defaults new registrations to DSI-only while keeping the Service-Provider option restorable without a data-model change.

**In scope:**
1. Colors, logo, and typography — replace navy/green/Rubik with DSSC's real Blue/Green/Jost+Open Sans across every page (homepage, About, Dashboard, wizard, reports, admin, auth pages).
2. Wording — "Questionnaire" → "Dataspace Maturity Assessment" in all user-facing text, plus "MAMI"/"CoE-DSC" → DSSC terminology (product name, email subject/sender, PDF filename, About page copy).
3. PDF report branding — same color/logo swap applied to `report.html`.
4. PDF content — a new section showing the initiative's actual submitted answers per question (not just aggregate scores/priority list).
5. Registration — hide the Service Provider option from the UI, default to DSI, without touching the `participant_type` schema/enum.

**Out of scope:** the underlying scoring math, questionnaire wizard mechanics, report data contract's dual-visualization logic (all Phases 14-16, done and untouched by this phase) — this phase only touches presentation/wording/PDF-content/registration-UI, not computation.

</domain>

<decisions>
## Implementation Decisions

### DSSC Brand Identity (BRAND-01, BRAND-03)
- **D-01:** Logo assets — primary full-color logo (`DSSC_logo_4c.png`) on light backgrounds (nav bar, login/register/forgot-password/reset-password pages, homepage main sections), white logo (`DSSC_logo_white.png`) on dark navy backgrounds (`Footer.tsx`, homepage hero gradient section in `index.tsx`). Both files currently live in `.planning/milestones/Design assets/` and must be copied into the frontend codebase (e.g. `frontend/src/assets/`) during implementation — they are not yet in a location the app can import from.
- **D-02:** Primary color = **Blue #008ecf** (replaces navy #06004f as `colorPrimary` — nav highlights, active states, buttons, headings). Accent/secondary = **Green #76b82a** (replaces old green #399e5a as `colorSuccess`/`colorLink`). Validated against the live `dssc.eu` site (fetched during this discussion): blue is genuinely DSSC's dominant primary color in practice, not just on paper in the manual — white/light nav, dark footer with the white logo variant, consistent with D-01/D-05.
- **D-03:** Secondary palette from the manual — Amber #fbbc43, Purple/slate #50568e, Grey #627179 (CMYK values also documented) — not mapped to specific UI roles this phase; available at planner/executor discretion for future accents (e.g. status badges) if a clear use arises.
- **D-04:** Typography — replace Rubik entirely with **Jost** (headlines/highlights/quotes, bold/medium weights) + **Open Sans** (body text, light/regular/semibold/bold), per the manual exactly. Both are freely available on Google Fonts.
- **D-05:** Page background — drop the colored-tint layout background (`colorBgLayout: rgba(57,158,90,0.1)`) entirely; use plain white/neutral grey, matching `dssc.eu`'s own clean light background.
- **D-06:** PDF report header — keep the existing colored header-band structure in `report.html` (driven by the `--primary` CSS var), recolored to DSSC Blue #008ecf, with the white logo variant placed on it. Smallest structural change — preserves the current `report.html` layout rather than restyling to a white/transparent header.

### PDF Submitted-Answers Section (RPRT-05)
- **D-07:** Grouped by the 6 categories (Governance, Business, Legal, Interoperability, Control over Data & Trust, Value Creation), in the same order as the radar chart/priority list; questions listed in config order within each category block.
- **D-08:** Each question row shows: question text + selected answer label + its 1-5 score. The existing `maturity_bands` color-band config (Phase 16's D-05, in `config/dssc-questionnaire.json`) may be reused to color-code each row/score, consistent with how the priority list already colors scores — exact visual treatment is planner/executor discretion.
- **D-09:** Section placement — **after** the existing radar chart + priority list sections (before/alongside the closing "expert help" CTA box). Preserves the current report narrative (scores/priorities first, detailed answers as a reference appendix at the end) rather than leading with raw answers.
- **D-10:** **PDF-only for this phase** — the in-app `/report` page does NOT need this new answers section. RPRT-05's literal text only calls out "the mailed/downloaded PDF report." This is a deliberate narrower reading than Phase 16's "one shared JSON contract" precedent (D-01/D-02 there) — the per-question answer data does not need to be added to the shared `/report/data` JSON contract consumed by both surfaces, only to the PDF-specific rendering path.

### Legacy Wording Scope (BRAND-02)
- **D-11:** "MAMI" (the old framework/product name) is renamed to DSSC terminology everywhere user-facing — not just the literal string "Questionnaire". This includes: page titles/headings ("About MAMI", "MAMI Questionnaire" heading), email subject/sender name ("MaMi Checker" / "Your MAMI Interoperability Heatmap"), the PDF filename ("MAMI-Interoperability-Report.pdf"), and About page copy. Exact final product display-name wording is Claude's discretion (e.g. "DSSC Maturity Scan" — PROJECT.md's milestone name is the natural default).
- **D-12:** "Questionnaire" → "**Dataspace Maturity Assessment**" applies to all user-facing text found during scouting: nav labels (`Sidebar.tsx`, `TopNav.tsx`), page headings, loading/empty/error copy, buttons ("Retake Questionnaire"/"Start Questionnaire"), and admin UI copy/labels. Does **NOT** apply to internal-only names — route/file names (`questionnaire.tsx`, `questionnaire.py`), component names (`QuestionnairePage`), API route paths, React Query cache keys (`"questionnaire-config"`, etc.), or backend service module names (`mami_config.py`) — renaming those is pure internal refactor with no user-facing effect and unnecessary churn for this phase.
- **D-13:** Contact domain/email — replace `coe-dsc.nl` links with **`dssc.eu`** (confirmed live site) and `info@coe-dsc.nl` with a placeholder **`info@dssc.eu`**, pending the real contact address.

### Registration Default (REG-01)
- **D-14:** The DSI/SP toggle in `register.tsx` **stays in the code but is feature-flagged off** (e.g. a `SHOW_PARTICIPANT_TYPE_TOGGLE` constant set to `false`). When off, the form always submits `participant_type: "DSI"`. Restoring the SP option later is a one-line flip of the constant — no JSX rewrite and no backend/data-model change needed (confirmed: `participant_type` is already nullable/unenforced on `Initiative`/`User` per Phase 13's D-12, and `schemas/auth.py`'s `Literal["DSI","SP"] = "DSI"` needs no change).

### Claude's Discretion
- Exact final product display-name wording (D-11) — e.g. "DSSC Maturity Scan" vs "DSSC Maturity Scan for Dataspaces".
- Exact visual treatment/use (if any) of the secondary palette (D-03) this phase.
- Exact color-coding mechanics for PDF answer rows (D-08) — literal `maturity_bands` reuse vs. a simpler treatment.
- Exact heading/wording for the new PDF answers section (D-09).
- File/asset naming once the logo PNGs are copied into the frontend codebase (D-01) — e.g. `logo-dssc-color.png`/`logo-dssc-white.png`.

</decisions>

## Specific Ideas

The manual is explicit that classic stock photos and photomontages are excluded from DSSC's visual language (page 10) — no imagery changes were otherwise discussed in this session, but this should be kept in mind if any future phase touches imagery.

The user uploaded the real brand assets mid-discussion (style-guide PDF + two logo PNGs) after being asked whether they had them ready — this is why the brand-identity decisions above are concrete color/font/logo choices rather than placeholders.
