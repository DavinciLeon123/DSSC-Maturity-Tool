## Phase Boundary

Three independent, user-requested feature/content changes, inserted after Phase 16 (same dependency pattern as sibling decimal phases 16.1/16.2/16.3): a mandatory data-collection consent checkbox at registration, an expanded 5-tier maturity scoring scale (replacing the current 3-tier one), and a contact/feedback CTA on the completed-assessment report page.

## Requirements (verbatim from user, unedited)

### Requirement (1) — Registration consent checkbox
Upon registration, as a user I need to agree that the data from the assessment is collected and stored by DSSC. If a user doesn't tick that box, the user won't be able to register an account. Since we only have test users, you may make it a fact that every test user has ticked that box.

**Interpretation note (not the user's words, flagged for discuss-phase/plan-phase):** "make it a fact that every test user has ticked that box" most naturally reads as: backfill/set existing users' consent state to true (e.g. via a migration default or a one-time data fix) rather than retroactively blocking currently-registered test accounts from logging in. The new checkbox requirement (ticking mandatory to register) should only gate the registration flow going forward. Confirm this reading during discuss-phase/research rather than assuming — in particular, whether this needs a new DB column (e.g. `User.data_consent: bool`) with a migration, and what the checkbox's exact label text should say (DSSC's real wording, if any exists, vs. Claude's discretion).

### Requirement (2) — Expand maturity-band scoring from 3 to 5 tiers
The final scoring now shows as "Needs Attention", "Developing" and "Mature". This should grow from 3 to 5 categories, as follows:
1.00 - 1.49: Exploratory
1.50 - 2.49: Prepatory
2.50 - 3.49: Implementation
3.50 - 4.49: Operational
4.50 - 5.00: Scaling

**Interpretation note:** the user wrote "Prepatory" — almost certainly a typo for "Preparatory". Confirm the exact intended spelling with the user before shipping user-facing copy (do not silently guess in the final label without flagging it). This is a maturity-BAND relabeling/re-banding, distinct from the existing red/orange/green color-band system (`maturity_bands` in `config/dssc-questionnaire.json`, established in Phase 16) — clarify during research/planning whether the 5 new tiers replace, supplement, or need to be reconciled against the existing 3-color banding used for chart/priority-list/PDF status dots (Phase 16, 16.3's bug #5a). The 3 old tier names ("Needs Attention"/"Developing"/"Mature") appear wherever final aggregate scoring is displayed — likely the in-app report page, the PDF report, and possibly the admin aggregate/heatmap view; research must find every occurrence, not just the most visible one.

### Requirement (3) — Report page contact/feedback CTA
On the report page, when a user has completed the assessment and sees his scoring, there should be a text together with a button that reads something like "Thank you for taking this assessment. If you have feedback or would like to have a conversation with an expert about your results, please click below to contact us" and then a button with a mailto:info@dssc.eu link.

**Interpretation note:** "the report page" most likely means the in-app `/report` route (`frontend/src/routes/_app/report.tsx`), not (or not only) the PDF — the user says "when a user... sees his scoring," which describes the live in-app view. Research/discuss-phase should confirm whether this CTA belongs in the PDF too (the PDF already has a similar "Get expert help" box per Phase 16.3's bug #5b fix — this new CTA may be redundant with that, complementary to it, or intended to replace/consolidate with it). Exact button/link wording ("click below to contact us") is "something like" per the user — some latitude on final copy, but the mailto target (`info@dssc.eu`) and the core message (thanks + feedback/expert-conversation invitation) are locked.
