# Phase 16.4 Plan 01: Consent Checkbox Summary

**Mandatory data-collection consent at registration: `User.data_consent` backfilled True for every existing/test user via a single-step Alembic migration, enforced server-side by a Pydantic validator (422 on false/missing) and client-side by a required, unchecked-by-default antd Checkbox disabling the Register button.**

## Accomplishments
- `User.data_consent` column added via a single-step `ADD COLUMN ... NOT NULL DEFAULT true` migration (`l3c4d5e6f7a8`, chained from head `k2b3c4d5e6f7`) — every existing row, including every test-factory-created user, is atomically consented with no separate backfill step
- `UserCreate.data_consent` (no schema default) + `validate_data_consent` field_validator is the real enforcement gate: `data_consent: false` or omitted → 422, never creates a user
- `register()` persists `data_consent` on the new `User` row
- `register.tsx` gained a required, unchecked-by-default antd `Checkbox` (D-05 placeholder copy, flagged in-code) that disables the submit `Button` until ticked, plus a `handleSubmit` early guard as defense in depth
- `docs/api/openapi.json` regenerated — `UserCreate` schema now includes required `data_consent`; verified deterministic (zero diff on a second consecutive export)
